# Progress: 2026-11-26

## Summary
Phase 3 (memory) was finished and released as v0.3.0, and Phase 4 (processes and permissions) is
two thirds done. The kernel now runs with the MMU on under a least-privilege mapping, has a page
allocator and a heap, runs preemptively scheduled threads, and runs user programs at EL0, each in
its own address space, which reach the kernel only through system calls (10 commits, 45 files,
about 2,900 lines).

## Completed
- **Phase 3, memory (released as v0.3.0, `6a0d40c`):**
  - Physical page allocator: one bitmap bit per 4 KB page; the kernel, loader memory and the
    Device Tree are kept back (`5b25df2`).
  - MMU on with an identity map: RAM cached, device registers uncached, everything else unmapped
    (`c44f066`). The roadmap item was split in two.
  - Kernel mapped with least privilege: code read-only, data never executable, page 0 unmapped,
    W^X enforced (`108a7e2`).
  - Kernel heap: `kmalloc` / `kzalloc` / `kfree` with size classes, refusing double frees
    (`e73a512`).
- **Phase 4, processes and permissions:**
  - Kernel threads and context switch (`5b1279a`).
  - Preemptive round-robin scheduler with 20 ms time slices (`da591e5`).
  - User mode and system calls (`write`, `yield`, `exit`); a faulting program is killed, not
    the kernel (`0ae4993`). The roadmap item was split in two.
  - Per-process address spaces with ASIDs, so programs cannot see each other's memory
    (`760974e`).
- **Project:** commits are now authored by sokpheng001 (GitHub no-reply address) with kwan and
  oda as co-authors, so GitHub lists the account as a contributor. File headers still name all
  three authors.
