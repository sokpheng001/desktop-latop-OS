# Progress: 2026-11-27

## Summary
Phase 4 (processes and permissions) was finished and released as v0.4.0, and Phase 5 (storage)
is well under way. Programs now carry a permission set checked by the kernel and can send each
other messages, and the kernel can read and write disks on both boards: a virtio disk on QEMU
`virt` and the SD card on the Raspberry Pi 4. The test disk is now a real FAT32 file system,
built by our own host tool (9 commits, 42 files, about 2,300 lines).

## Completed
- **Phase 4, processes and permissions (released as v0.4.0, `d7c440c`):**
  - Per-process permissions (console, files, network, camera, microphone), checked by the kernel
    on every system call. A program can drop permissions but never regain them (`8dd75fc`).
  - Message passing between processes: synchronous send and receive of two-word messages, with
    the sender's id stamped by the kernel so it cannot be forged (`f4dcbcb`).
- **Phase 5, storage:**
  - Version moved to 0.5.0-dev (`6b4b72b`).
  - virtio devices found through the Device Tree; the block device identified, its size read
    and its features negotiated (`e081584`).
  - virtio disk: sectors read and written through a request queue (`a187e3f`).
  - SD card found on the Raspberry Pi 4: controller reset, card identified, size read
    (`6878928`).
  - SD card: blocks read and written; both disks are registered as block devices behind one
    interface (`50a9de0`).
  - FAT32 test disk built by our own host tool, `tests/mkfat32.c`, written from Microsoft's FAT32
    specification. macOS recognises the image and `fsck` reports it clean (`646fa45`). The
    roadmap item was split in three.

## Build and tests
`make test` on `dev` at `646fa45`: all pass. The full suite also passed in a Debian trixie
container that mirrors CI, before the v0.4.0 release and again at `646fa45`.

| Board | Boot runs | Result |
|---|---|---|
| QEMU `virt` | normal, EL2 entry, fault, abort, IRQ, timer, page allocator, read-only data, no-execute, NULL, heap, threads, scheduler, user mode (with permissions and messages), disk | 15/15 PASS |
| QEMU `raspi4b` | the same, without EL2 entry | 14/14 PASS |
| Host | `lib_test` (strings, `kprintf`, Device Tree, page allocator, heap) | PASS |

The disk tests also check the disk image file on the host after the run, so a driver that
writes to the wrong place cannot pass by reading back its own mistake. Each new feature was
checked with a control test: the feature was deliberately broken and its test had to fail.
