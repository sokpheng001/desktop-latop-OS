# Progress: 2026-11-25

## Summary
First full working day. The project went from documents only to a kernel that boots on QEMU
`virt` and the Raspberry Pi 4 model, handles exceptions and interrupts, runs a 100 Hz timer and
reads its RAM layout from the Device Tree. Phases 1 and 2 are finished and released as v0.1.0
and v0.2.0; Phase 3 has started (30 commits, 72 files, about 3,900 lines).

## Completed
- **Project setup:** vision, hardware targets, roadmap, changelog, contribution rules, research
  notes (`1e1b92b`, `0113384`, `6259dc8`, `d29be08`, `677b926`, `7a6e1d1`); the "two systems in
  one" goal: a complete normal OS and a human-AI system (`d143c9b`); a creation date in every
  file header (`6c81d14`).
- **Phase 1, first boot (released as v0.1.0, `17cdb77`):**
  - Folder structure and `Makefile` (`5c3961d`); base headers (`6bf1854`); linker scripts
    (`9efdef6`); AArch64 boot entry (`4aca02b`).
  - HAL interface (`8a22d0b`), PL011 UART driver (`278f5d0`), `memset`/`memcpy`/`strlen` and
    `kprintf` (`308a959`), boot banner on both boards (`cde989c`).
  - QEMU boot test in `make test` (`5f36d9c`), Linux toolchain fixes (`13583e6`), GitHub
    Actions CI (`d05d2de`).
- **Phase 2, exceptions and time (released as v0.2.0, `3eb6fcb`):**
  - Drop from EL2 to EL1 at boot (`533b4dd`).
  - Exception vectors with fault reports (`bc3afb7`).
  - GICv2 interrupt controller and IRQ dispatch (`ae2a373`).
  - 100 Hz timer tick and uptime counter (`20d18f2`).
  - Tests for data aborts and unhandled IRQs (`f54bbf2`).
- **Phase 3, item 1:** read RAM layout from the Device Tree (`1cc6bca`). The kernel image now
  carries the arm64 image header so firmware and QEMU pass the Device Tree; a host unit test
  covers 64-bit values, several memory nodes and a corrupt header.
